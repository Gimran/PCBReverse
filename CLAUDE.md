# PCBREVERCE — инструмент реверса печатных плат

Одностраничное веб-приложение (`index.html`, ~1500 строк, без сборки и зависимостей)
для совмещения фото/сканов сторон платы и герберов, разметки нетов и установки
SMD-компонентов. Выросло из проекта GN1144 (SFP+ 10G), теперь самостоятельный проект.

## Пользователь и стиль работы
- В UI можно английские термины там, где русский выглядит нелепо: **NET / NETS** вместо «нет/неты», main и т.п.
- Инженер-разработчик электроники (Altium, hi-speed PCB до 8 слоёв, монтаж). Сам пользуется инструментом.
- Отвечать по-русски, кратко, без лишней вежливости; строго по задаче; не предлагать непрошеные альтернативы.
- UI-тексты на русском. Замечания пользователя приходят со скриншотами — правка должна попадать точно в показанное место.
- Перед крупной переделкой — бэкап текущей версии в `backups/` с датой и смыслом в имени.

(IBM Plex Sans / Sans Condensed / Mono) с системным fallback.

## Раскладка UI
- **Левая панель**, вкладки (`data-ltab`/`data-lpage`): **ВИД** (по умолчанию) — переворот платы, XRAY, показ нетов/
  компонентов, поворот/отражение вида, вписать, сетка, инверсия; **СЛОЙ** — активный слой: угол/масштаб (слайдер + поле),
  ручная деформация M, кроп, сбросы, удаление фона, коррекция цвета; **ДЕФОРМ** — деформация по опорным точкам; **КОМП** — калибровка масштаба,
  установка R/C, свойства, список; **?** — шпаргалка клавиш.
- **Центр** — рабочее поле (`#vp`): стек слоёв + SVG-оверлей `#marks` (точки, пары, компоненты) + HUD.
- **Правая панель**, вкладки: **СЛОИ** (режим просмотра все/только актив/шторка, опора, карточки слоёв),
  **НЕТЫ**, **ФАЙЛЫ** (без текстовых подсказок — только title; «+ Добавить слой», папка картинок; на слой — имя, сторона, ✕, путь,
  «Выбрать файл…»/«Перечитать файл», статус только при ошибке «не загружен»,
  «Сохранить проект» / «Загрузить проект» *.pcbr).
- Список слоёв сгруппирован по метке: TOP сверху, BOT, «обе» внизу, с разделителями `.lsep`. Порядок стека = порядок
  групп (`restack()` сортирует стабильно: обе < BOT < TOP), ▲▼ двигают только внутри группы, смена метки переносит слой.
  Количество слоёв произвольное (справочные слои с даташитов): `addLayer()` — новый слой на стороне `boardSide`, сверху
  группы, активный, сразу открывает выбор файла; `removeLayer()` — с confirm, удаляет его точки нетов и пары. Клавиши 1…8 —
  видимость первых 8 слоёв стека.
- Карточка слоя — 3 строки: [цвет · имя · метка TOP/BOT/обе · ▲ ▼ · глаз] / [α-слайдер % · режим наложения] /
  [цвет тонировки · слайдер % · режим тонировки] + строка ⇄ ⇅ ↺ ↻. Выпадающие списки — минимальной ширины,
  сокращённые подписи, полное имя в title. Имя слоя редактируется только во вкладке ФАЙЛЫ.
- Тема: токены на `:root`, тёмная через `prefers-color-scheme` и `[data-theme]`.

## Модель координат (важно, здесь были баги)
- **image px** — пиксели изображения слоя при CSS-ширине 1200 px (`l.w=1200`, `l.h` из naturalHeight).
- **world** — общая система сцены, начало в центре `#vp`.
- **screen** — пиксели вьюпорта.
- Слой → world: либо ручной `T(l,p)` (центр, flip fh/fv, scale, rot, сдвиг x/y), либо гомография `l.H`
  (8 чисел, image px → world), если применена деформация. `worldOf/imgOf` выбирают сами.
- Вид: `.scene` имеет `translate(view.x,y) scale(z*±1, z*±1) rotate(view.rot)`.
  `screenOf/worldFromEvent/screenDelta` учитывают поворот и оба отражения. Любое новое взаимодействие с мышью —
  только через эти функции. Перетаскивания двигают объект по экранным осям при любом виде.
- Деформированный слой рисуется через `matrix3d` на `.lbox` с `transform-origin:0 0`, `left/top:50%`.
- Точки нетов и опорные пары хранятся в image px своего слоя → едут вместе со слоем.
  Компоненты — в world (свои «слои» top-comp/bot-comp, к изображениям не привязаны, по решению пользователя).

## Деформация по опорным точкам
- Клик по опоре (`refId`), затем та же точка на активном слое (`sel`); до 8 пар; пары хранятся в слое (`l.pairs`, поле `rl`).
- `fitTransform(src,dst,{mirror,model})`:
  - 2 пары → подобие; **зеркальность берётся из ручных ⇄/⇅ слоя (`baseMirror`)** — иначе зеркальный слой
    переворачивался (баг, найден на реальных данных: 3-я точка уезжала на 172 px).
  - ≥3 → аффинная МНК (по умолчанию; сканы и герберы).
  - ≥4 и выбрана «перспектива» → гомография DLT с нормализацией.
  - Если det результата противоречит ориентации слоя — красное предупреждение в статусе.
- Пары рисуются тонкими чёрными крестами «+» (опора крупнее, номер рядом, прозрачность ~55%) — не путать с точками нетов.
- Мигание слоя, по которому ждётся клик (отключаемо), только в режиме опорных точек.

## Режимы клика (`clickMode`)
`none` | `align` (P) | `net` (N, «Редактирование нетов») | `comp` (K, «Редактирование компонентов») | `calib` |
`move` (M, «Ручная деформация») | `crop` («Кроп слоя»). Изображение слоя двигается **только** в `move`.
Стек картинок: `pointer-events:none`, `draggable=false`, `dragstart/selectstart` подавлены — иначе Chrome
начинал нативный drag картинки. Панорама — только средней кнопкой. Колесо — зум к курсору.
Правый клик / Delete удаляют только в своём режиме: точку нета — в `net`, компонент — в `comp`; в остальных ничего.
Правка компонентов (перетаскивание, стрелки, Space, свойства, ✕/«Удалить» в панели) — только в `comp`; вне режима
компонент можно лишь выбрать кликом (в `none`) и посмотреть свойства — поля неактивны (`compEditShown` перерисовывает
панель при смене режима). В `net`/`align` клик идёт сквозь компонент. Удаление точки кнопкой в НЕТАХ — только в `net`.

## Прочее поведение
- Переворот платы (F): `boardSide` top↔bot, `view.fh` инвертируется, видны слои с меткой текущей стороны или «обе»;
  вручную скрытый слой не включается; showSide компонентов переключается.
- XRAY (кнопка рядом с «Перевернуть», поле `xray` в snapshot): фильтр по стороне отключён (`onSide()`), видны слои
  и компоненты обеих сторон; переворот при этом только отражает вид. Выключение XRAY возвращает showSide по `boardSide`.
- Удаление фона (вкладка СЛОЙ, поля слоя `kOn`/`kc`/`kt`, по умолчанию белый, допуск 15%): в начале того же SVG-фильтра
  цветовой ключ — две feColorMatrix (c−key)+ и (key−c)+ → сумма = |c−key| → alpha = (Σ − kt·1.5)/0.06 → `in` с
  SourceGraphic = результат `src`, дальше тонировка работает от `src`. Пипетка — `EyeDropper` (Chrome), берёт цвет с экрана.
- Коррекция цвета (вкладка СЛОЙ, `l.cor` = `COR0` {lb,lw,gm,br,ct,sat,sh,pz}, UI из `CORUI`, двойной клик по ползунку —
  сброс параметра, пресеты «подписи» / «ЦВ подписи» / «порог Ч/Б» / сброс). «ЦВ подписи» = «подписи» + чёрн 100% и
  ставит штатную тонировку слоя: режим «осв» (screen) 100% цветом тонировки слоя; «сброс» тонировку не трогает. Цепочка фильтра: ключ фона → `k0` → резкость
  (feConvolveMatrix) → уровни (linear) → гамма → контраст/яркость (linear) → насыщенность (saturate) → постеризация
  (discrete) → `src` → тонировка. Фильтр включается только если что-то не по умолчанию (`corActive`).
- Тонировка: SVG-фильтр на `<img>` (feFlood → feComposite in → feBlend режим слоя → арифметическое смешение по %),
  не mask-image. Режим наложения слоя — `mix-blend-mode` на `.clip`, у нижнего слоя отключён; `#vp` isolation:isolate.
- Сторона новых компонентов (`compSide`, `autoCompSide()` в `sync`): по метке активного слоя TOP/BOT, для «обе» — `boardSide`.
  Пересчёт только при смене активного слоя / его метки / стороны платы; ручной выбор держится до этого. При установке
  фильтр showSide этой стороны включается — компонент не ставится невидимым.
- Цвет компонентов по стороне — `SIDECOL` (по умолчанию top #ff0000, bot #0000ff), меняется цветовыми полями рядом с
  фильтрами top-comp/bot-comp, хранится в snapshot как `sideCol`. Цвет слоя = цвет тонировки `l.tc`: полоска-метка в
  карточке и во вкладке ФАЙЛЫ (`.swatch[data-lid]`) перекрашиваются на месте при выборе цвета; `color` в snapshot = `tc`.
- Компоненты: R/C, 0201/0402/0603/0805 (реальные L×W×T в `PKG`), масштаб `mmScale` px/мм — одна калибровка на проект;
  поворот Space/Shift+Space ±45°; designator автоинкремент; value по умолчанию — последнее введённое для R / для C
  (`compVal`); выводы 1/2 привязываются к нетам,
  номера выводов подписаны на падах (скрываются, если пад на экране < 5 px).
  Новая точка нета в зоне вывода (`pinFromPoint`, ближайший видимый компонент) прописывает нет в этот вывод.
  `autoPins(c)`: точка нета видимого слоя в зоне вывода (своя половина корпуса + запас 15% L / 25% W) задаёт нет
  вывода; приоритет активному слою, затем ближайшая к паду. Вызывается при установке, перетаскивании, повороте,
  смене корпуса, сдвиге стрелками. Вывод без точки не трогается, кроме случая, когда его нет переехал на другой вывод.
- Переходное отверстие: Alt+клик в режиме N → точка с `via:true` (хранится в image px активного слоя). `ptShown()`:
  via видна всегда (обе стороны, любой режим просмотра), рисуется толстым кольцом, подпись `·via`; при попадании в
  зону вывода прописывает нет компоненту любой стороны.
- «Показать: неты / компоненты» (под XRAY; `showNets`/`showComps` в snapshot) — скрывают всё и выключают клик по скрытому;
  вход в режим N / K включает соответствующее.
- Вкладка NETS: верхний блок (режим N, статус, кнопки «+ NET / − точка / очистить / подписи» в один ряд) закреплён
  (`position:sticky`) при прокрутке списка.
- «+ NET» создаёт NET и ставит фокус в поле имени с выделенным текстом — можно сразу печатать; Enter/Esc — выйти из поля.
- Список нетов: слева в строке ручка `.grip` (▶ у активного) — клик выделяет/подсвечивает нет.
- Режим M «Ручная деформация» (как в CorelDRAW; только слой без деформации по точкам): рамка слоя, клик по слою без
  сдвига переключает `xfMode` масштаб ⇄ вращение (углы — квадраты / ↻). Центр ⊕ (`l.piv`, image px, не сохраняется,
  по умолчанию центр) — опора и масштаба, и поворота; тянется мышью, двойной клик — обратно в центр. Масштаб/поворот
  считаются от состояния на начало перетаскивания: t' = Pw + k·(t−Pw) / Pw + R(d)·(t−Pw). Shift — поворот шагом 15°;
  при зеркальном виде знак угла инвертируется. Перетаскивание в любом месте — сдвиг.
- Кроп слоя (режим `crop`, кнопка рядом): `l.crop` {x0,y0,x1,y1} в image px (сохраняется), рисуется `clip-path: inset()`
  на `<img>` — работает и на деформированном слое. Рамка с 8 маркерами (углы/стороны), внутри — сдвиг рамки,
  пунктир — полный кадр; «сброс кропа».
- Подписи нетов: 13 px с ореолом (`paint-order:stroke`), цвет ореола контрастный к цвету нета (`haloFor`).
- Видимость точек нетов = `layerShown(слой)` (глаз, сторона/XRAY, режим все/только актив/шторка; α не учитывается).
  `applyAll()` перерисовывает метки.
- Клавиши: 1…8 видимость слоя, X след. слой, R/Shift+R поворот вида, H/V отражение вида, F переворот платы,
  P/N/K/M режимы, Z отменить точку, Delete, Esc, стрелки, [ ] (±0.1°, Shift ×10). В полях ввода клавиши не срабатывают.

## Видеослой (экспериментально)
- Отдельная правая вкладка **ВИДЕО** (`renderVideo`, вызывается из `renderFiles`): «+ Видеослой» и блок на каждый
  видеослой — имя, сторона (обе/TOP/BOT), глаз, ✕, камера, статус, α, края, ⇄ ⇅ ↺ ↻, Старт/Стоп, обновить список,
  «Снимок → TOP/BOT main», «Снимок в слой». Клик по блоку делает слой активным (кроп/коррекция — во вкладке СЛОЙ).
  Видеослой НЕ показывается в СЛОИ и ФАЙЛЫ; в стеке всегда сверху.
- Видеослой: `kind:'video'`, в `.lbox` вместо `<img>` стоит `<video>` (`attachVideo`), поток
  `getUserMedia` (ideal 1920×1080, `camId` сохраняется). Фильтр (ключ/коррекция/тонировка) и `clip-path` кропа
  дублируются на `<video>`; геометрия, деформация по точкам — как у картинки. `l.h` из videoWidth/Height.
- Главные слои сторон: метка «TOP main» / «BOT main» в селекторе стороны (`sideSel`, поле `l.main`, один на сторону).
  «Снимок → TOP main» (`snapPatch`): кадр → обычный слой-картинка на месте видео (x/y/rot/scale/flip/H/crop/cor/fe),
  подслой главного слоя (`l.parent`): в стеке сразу над родителем, в списке с отступом ↳, ▲▼ среди соседей,
  скрыт, если скрыт родитель; в «только актив» виден вместе с родителем. Правится как любой слой (M, кроп, коррекция).
  Без гомографии — просто наложение с ручной деформацией (решение пользователя). Смена стороны отвязывает.
- Размытие краёв `l.fe` (доля от меньшей стороны кропа, 0…0.5): CSS mask из двух linear-gradient (intersect) внутри
  кроп-рамки, на `<img>` или `<video>`; ползунок «края» во вкладке СЛОЙ и в строке видеослоя (видео по умолчанию 15%).
- В .pcbr видеослой сохраняется без картинки (только настройки). Нужен secure context (file:// в Chrome — да).

## Сохранение
- Автосохранение настроек в localStorage, ключ `pcb-overlay-v4` (debounce 400 мс). У `file://` origin общий для всех
  локальных файлов.
- Картинки в браузере: оригиналы в IndexedDB `pcbreverse`/`img`, ключ = id слоя (`idb.get/put/del/clear`), `l.stored=true`,
  `l.blob` в памяти. Старые сохранения (webp ≤1600 px в localStorage `pcb-overlay-img-<id>`) читаются как запасной вариант;
  он же используется, если IndexedDB недоступна (`storeFileLS`).
- `snapshot()/restore()` — при добавлении поля правь обе функции + дефолт в `mkLayer`. restore терпим к старым
  сохранениям (голые имена файлов → дополняются `imgDir`).
- **Проект *.pcbr** (ФАЙЛЫ → «Сохранить проект» / «Загрузить проект»): zip без сжатия (store, свой `zipStore`/`unzip`,
  чтение понимает и deflate). Внутри `project.json` = `snapshot()` + у слоя поле `file` → `images/<id>_<имя>.<ext>`
  (оригинальные байты). Сохранение: `showSaveFilePicker`, иначе скачивание; имя = `projName` (из имени загруженного файла).
- С `file://` байты картинок, заданных только путём, недоступны (fetch запрещён, canvas «грязный») → при сохранении
  список таких слоёв и кнопки «Указать файлы…» (сопоставление по имени, файл кладётся в IndexedDB — больше не спросит)
  / «Сохранить без них». Загрузка проекта очищает IndexedDB и кладёт туда картинки из архива.
- «Загрузить проект» принимает и старый JSON-экспорт (.json).

## Как вносить правки
1. Бэкап в `backups/` перед заметной переделкой UI или логики.
2. Правка → `node -e` синтаксис-проверка скрипта → `node tests/smoke.js` (грузит `tests/test_project.pcbr`).
   Playwright локально не установлен (`npm i -D playwright`); без него — те же проверки в браузерной панели через
   `python -m http.server` и `loadProject(new File([await (await fetch('tests/test_project.pcbr')).blob()],'test_project.pcbr'))`.
3. Для UI — один скриншот области через Playwright и взгляд на него перед сдачей.
4. Проверять на `tests/test_project.pcbr`, а не только на пустой странице.
